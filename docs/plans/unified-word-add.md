# 単語の追加を 1 つの入口にまとめる（単語帳にある語・ない語を分けない）

作成日: 2026-11-03

## 目的・背景

- いまはグループに単語を入れる入口が **2 つ** ある
  - iOS: グループ詳細の「＋」メニュー / 空のときのボタンに「単語帳から追加」と「自分で単語を作る」
  - 管理画面: グループ詳細に「単語帳から追加」（検索）と「マイ単語を作って追加」（フォーム）の 2 セクション
- 初学者は **入れたい語が単語帳にあるかどうかを知らない**。先にどちらかを選ばせるのは判断の負担になり、
  「自分で単語を作る」から入ると、単語帳にある語や打ち間違いのまま自作語を作ってしまいやすい
  （エディタ内の重複案内・AI チェックで後から寄せてはいるが、入口の時点で分かれている）
- [ai-word-assist](archive/ai-word-assist.md) で「単語帳から追加」で見つからない → AI で調べて作る、の流れができたので、
  **入口を「単語を追加」1 つにし、まず検索 → あれば選ぶ・無ければその場で AI で調べて作る** に統一する

## 対応方針

### 流れ（iOS・管理画面共通）

1. 「単語を追加」を開く（入口はこれだけ）
2. 英語か意味を入れて検索する（同梱語 + マイ単語）
3. 結果があればチェックして選ぶ（今の「単語帳から追加」と同じ）
4. 検索語が入っていれば、**結果の有無にかかわらず** 一覧の末尾に
   「「○○」を AI で調べて追加する」（AI が使えないときは「自分で作って追加する」）を出す
   - 0 件のときは今と同じく空状態の中央に大きく出す
   - 結果があるときは、一覧の最後の行として控えめに出す（同じ綴りの語が結果にあればそれを選ぶのが先、と分かる文言にする）
5. 押すと検索語入りの自作語エディタを開き、AI チェックを自動で走らせる（今の `.pick` モードの動き）。
   AI が単語帳の語を見つけたらそれを選択に加え、無ければ下書きを確かめて作る

### Phase 1: iOS の入口を 1 つにする

- `GroupDetailView`
  - 「＋」メニューの「単語帳から追加」「自分で単語を作る」を **「単語を追加」1 つ** にする
    （メニューは「単語を追加」と「名前を変更」になる。「＋」を押したら直接ピッカーを開き、名前の変更はツールバーの別ボタンに移すのも検討）
  - 空状態のボタンも「単語を追加」1 つにし、説明文を「単語帳にない単語もここから作れます」に直す
  - `isCreatingWord` と `CustomWordEditorView(mode: .create(addingTo:))` の呼び出しを外す
- `WordPickerView`
  - タイトルを「単語を追加」に。検索欄の文言を「英語か意味で検索（単語帳にない語も追加できます）」などにする
  - 検索語があれば結果の末尾に作成の行を出す（上記 4）。検索語が空のときは、一覧の上に
    「単語帳にない単語は、検索欄に入れると作れます」と 1 行出す
  - 作成の行のロジック（出すか・文言）は View から切り出してテストできるようにする（例: `WordPicker.createAction(query:results:assistAvailable:)`）
- `CustomWordEditorView`
  - 新規作成は `.pick` だけになるので、`.create(addingTo:)` と `targetGroup` まわりの分岐を消す
    （編集 `.edit` は単語詳細から使うので残す）
  - 必要なら `.pick` を `.create(prefill:onPick:)` に改名して意図を分かりやすくする
- `DebugSeed`: `.wordEditor` は「ピッカーから commute を作る」状態で開くように変える（スクリーンショット確認用）

#### 追加（2026-11-03、実機確認で依頼）: AI で調べている間の表示

- エディタを開くと AI チェックが自動で走るようになり、待ち時間が目立つようになった。
  今は「AI チェック」欄に小さな `ProgressView` と文字だけで、処理中だと気づきにくい
- 待ち時間の行を `AssistLoadingView`（`Features/Groups/`）に切り出し、
  - きらめくアイコン（`sparkles` に `symbolEffect(.variableColor)`）と「「○○」を AI で調べています…」
  - その下に、候補が入る場所の骨組み（灰色のバー）をゆっくり明滅させる
  - 「視差効果を減らす」がオンなら動かさない。VoiceOver には 1 つの文として読ませる
- 画面確認用に `DebugSeed` に `word-editor-loading`（エディタを調べている途中の状態で開く）を足す

#### 追加（2026-11-03、実機確認で依頼）: 開いたら検索欄にフォーカス

- 「単語を追加」を開いた直後に検索欄へフォーカスを当て、すぐ入力できるようにする（`DebugSeed` の画面確認時はそちらを優先）

#### Phase 1 の結果（2026-11-03）

- Swift Testing 172 件成功（`WordPickerTests` 含む）・SwiftLint 警告 0・シミュレータと実機で確認
- macOS 27.2 + Xcode 26.5 ではテストランナーがシミュレータに接続できず（「The test runner hung before establishing connection」）、
  Xcode 27.2 に更新して解消。あわせて Xcode 27 の警告（`ModelContext` を使うファイルに `import SwiftData` が無い）と、
  `devicectl` の識別子が UDID 形式になって `run-ios-device.sh` が端末を選べなくなった件を直した

### Phase 2: 管理画面のグループ詳細を 1 つの流れにする

- 「単語帳から追加」と「マイ単語を作って追加」の 2 セクションを **「単語を追加」1 セクション** にまとめる
  - 検索フォーム → 結果の表 → 表の下に「「○○」をマイ単語として作る」
  - 作成フォームは検索語があるときだけ表示し、検索語を下書きに入れる（今の `draftFromQuery`）。
    AI が使えるときは表示と同時に「AI で調べる」を自動で走らせる（`data-assist-autorun` のような属性を足し、`SCRIPT` で拾う）
  - 検索語なしで直接フォームに入る入口は無くす
- マイ単語ページ（`/admin/custom-words`）の作成フォームはグループに入れない単体作成なので、今回は **そのまま**（対象外）

### Phase 3: 後片付け

- 文言（「自分で単語を作る」「マイ単語を作って追加」など）の残りを `grep` で確認
- `docs/specs` に登録の流れが書かれていれば更新

## 影響範囲

- iOS: `Features/Groups/GroupDetailView.swift`、`WordPickerView.swift`、`CustomWordEditorView.swift`、`App/DebugSeed.swift`
  （新規にピッカーの判定を置くなら `Core/` か `Features/Groups/` にロジック用の型を足す）
- server: `src/admin/pages.ts`（グループ詳細）、`src/http/html.ts`（AI チェックの自動実行）、関連テスト
- データ・同期・出題には影響しない（作られる自作語・グループの中身は今と同じ）

## テスト方針

- iOS（Swift Testing）
  - 作成の行の判定: 検索語が空なら出さない / 0 件でも結果ありでも出す / AI の有無で文言が変わる / 前後の空白は落とす
  - 既存の `WordDraft.prefilled(fromSearch:)`（英語なら英語欄、日本語なら意味欄）がそのまま通ること
  - 既存テストがすべて通る・SwiftLint 警告 0
- server（Vitest）
  - グループ詳細: 検索語なしでは作成フォームが出ない / 検索語ありでは結果の有無にかかわらず作成への導線とフォームが出る /
    AI 有効時は自動実行の属性が付く
  - 既存の自作語作成・重複案内のテストが通る
- 画面確認
  - シミュレータ: グループ詳細の「＋」→ 検索 → 単語帳の語を選ぶ / commute（単語帳に無い）を AI で作る / beautifull で単語帳の語に寄る
  - 管理画面: ローカルで同じ 3 パターン
