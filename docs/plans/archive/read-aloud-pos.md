# グループの読み上げに品詞の表示と読み上げを入れる

作成日: 2026-11-07

## 目的・背景

- グループの読み上げ（`ReadAloudView`）は「単語 → 意味 → 例文 → 例文の和訳」を読む。品詞は、意味が 2 つ以上あるマイ単語のときだけ画面に出していて、声では読んでいない
- 聞き流すだけでも品詞が分かるよう、どの語でも品詞を画面に出し、声でも読む

## 対応方針

- **画面**: 読んでいる語のカードで、意味の前に品詞のラベル（「名詞」「動詞」「熟語」など）をいつも出す（今は意味が複数のときだけ）
- **声**: 意味の文の頭で品詞を読む。「名詞。りんご」のように、意味の文（`ReadAloudLine.Kind.meaning`）の声に出す文（`spokenText`）の頭に「品詞。」を付ける
  - 品詞を別の文にしないのは、Gemini の TTS への頼みが 1 語あたり 1 つずつ増え（音声を作る待ち・回数制限）、文と文の間の間も増えるため
  - 画面の文（`text`）は意味のまま。意味の文を読んでいる間は、品詞のラベルも意味と一緒に強調する
  - 意味が複数ある語は、意味ごとにその意味の品詞を読む
  - 日本語の声が無い端末（日本語の文を入れないとき）は、意味と一緒に品詞も読まない（今までどおり）
- 意味の声の文が変わるので、端末に残してある意味の音声は使われず、次に読むときに作り直す（単語・例文・和訳の音声はそのまま使える）
- 学習中の読み上げ（単語 → 例文）・穴埋めの回答後の読み上げは変えない

## Step

1. 実装（画面の品詞・意味の文の頭で品詞を読む・テスト）
2. 実機確認（Gemini の声で「名詞。りんご」が自然に聞こえるか。品詞と意味の間の間・「熟語」「限定詞」などの読み方）

## 影響範囲

- `Features/Groups/ReadAloudView.swift`（品詞のラベル）

- サーバー・データは変えない

## テスト方針

- Swift Testing（`ReadAloudTests`）: 意味の文の声が「品詞。意味」になる（画面の文は意味のまま）・意味が複数ある語は意味ごとの品詞を読む・記号を整えた意味に品詞が付く
- SwiftLint 警告 0
- シミュレータで `group-read-aloud` を開き、品詞のラベルが出て、意味と一緒に強調されることを見る（声は DebugSeed の偽のサーバーの音なので、Gemini の声での聞こえ方は実機で確かめる）
