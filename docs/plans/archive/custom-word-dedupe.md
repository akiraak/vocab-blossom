# 同じ綴りのマイ単語を 1 つだけにする

作成日: 2026-11-03

## 目的・背景

- 実機で commute を「AI で調べる → 追加」し、グループから外して試し直すたびに、マイ単語の commute が増えた（3 つ）
- グループから外してもマイ単語は残る（仕様）。検索するとその commute が「単語帳」に並ぶが、「AI で調べる → 追加」で
  もう 1 つ作れてしまう。同じ綴りのマイ単語が既にあっても新しく作るのを止めていない
- ユーザーの指示: AI で作ったもの（マイ単語）は 1 つだけ残す。検索したとき作ってあるものがあれば、それと「AI で調べる」ボタンの 2 つを出す

## 対応方針

- 「単語を追加」で新しく作る語を確定するとき、同じ綴り（大小文字・前後の空白は無視）のマイ単語があれば、
  新しく作らずにその内容（意味・品詞・例文）を置き換える。ID はそのままなので学習の記録は残る（`GroupEditor.upsertCustomWord`）
- 同じ綴りのマイ単語が複数あれば、いちばん新しく更新したものに寄せる。ほかはグループでの位置を寄せる先に引き継いでから消す
  （削除記録が同期でサーバー・ほかの端末にも届く）
- 表示: 検索結果のマイ単語の行と「AI で調べる」は今も両方出る。同じ綴りのマイ単語があるときは、
  「AI で調べ直して追加すると、このマイ単語の内容を置き換えます」と添え、AI の結果のカードは「新しく作る」ではなく「置き換える」と出す
- 管理画面（サーバー）の自作語の作成はこのタスクでは変えない

## 影響範囲

- iOS: `Core/GroupEditor.swift`、`Features/Groups/WordPicker.swift`・`WordPickerView.swift`、テスト

## テスト方針

- Swift Testing: 同じ綴りが無ければ作る / あれば置き換えて ID が変わらない / 複数あれば 1 つに寄せ、グループの位置を引き継ぎ、
  ほかは削除記録を残して消える / 大小文字の違いも同じ綴り / 作成の導線の文言
- 既存テストがすべて通る・SwiftLint 警告 0
- 実機: commute を追加し直して 1 つにまとまることを確かめる

## 結果（2026-11-03）

- `GroupEditor.upsertCustomWord`: 同じ綴りのマイ単語が無ければ作り、あればいちばん新しく更新したものの内容を置き換える（ID・学習の記録はそのまま）。
  ほかの同じ綴りのマイ単語は、グループでの位置を寄せる先に引き継ぎ（すでに寄せる先が入っているグループでは外すだけ）、削除記録を残して消す
- 「単語を追加」の「追加」で新しく作る語は `upsertCustomWord` で保存する。寄せて消した語を一覧から選んでいた場合は、その ID をグループに入れない
- 文言: 同じ綴りのマイ単語が検索結果にあれば「AI で調べ直して追加すると、そのマイ単語の内容を置き換えます（学習の記録は残ります）」。
  AI の結果のカードは「置き換える」
- Swift Testing 202 件成功・SwiftLint 警告 0
