# 単語の追加を 1 つの入口にまとめる（単語帳にある語・ない語を分けない）

作成日: 2026-11-03

## 目的・背景

- いまはグループに単語を入れる入口が **2 つ** ある
  - iOS: グループ詳細の「＋」メニュー / 空のときのボタンに「単語帳から追加」と「自分で単語を作る」
  - 管理画面: グループ詳細に「単語帳から追加」（検索）と「マイ単語を作って追加」（フォーム）の 2 セクション
- 初学者は **入れたい語が単語帳にあるかどうかを知らない**。先にどちらかを選ばせるのは判断の負担になり、
  「自分で単語を作る」から入ると、単語帳にある語や打ち間違いのまま自作語を作ってしまいやすい
  （エディタ内の重複案内・AI チェックで後から寄せてはいるが、入口の時点で分かれている）
- [ai-word-assist](archive/ai-word-assist.md) で「単語帳から追加」で見つからない → AI で調べて作る、の流れができたので、
  **入口を「単語を追加」1 つにし、まず検索 → あれば選ぶ・無ければその場で AI で調べて作る** に統一する

## 対応方針

### 流れ（iOS・管理画面共通）

1. 「単語を追加」を開く（入口はこれだけ）
2. 英語か意味を入れて検索する（同梱語 + マイ単語）
3. 結果があればチェックして選ぶ（今の「単語帳から追加」と同じ）
4. 検索語が入っていれば、**結果の有無にかかわらず** 一覧の末尾に
   「「○○」を AI で調べて追加する」（AI が使えないときは「自分で作って追加する」）を出す
   - 0 件のときは今と同じく空状態の中央に大きく出す
   - 結果があるときは、一覧の最後の行として控えめに出す（同じ綴りの語が結果にあればそれを選ぶのが先、と分かる文言にする）
5. 押すと検索語入りの自作語エディタを開き、AI チェックを自動で走らせる（今の `.pick` モードの動き）。
   AI が単語帳の語を見つけたらそれを選択に加え、無ければ下書きを確かめて作る

### Phase 1: iOS の入口を 1 つにする

- `GroupDetailView`
  - 「＋」メニューの「単語帳から追加」「自分で単語を作る」を **「単語を追加」1 つ** にする
    （メニューは「単語を追加」と「名前を変更」になる。「＋」を押したら直接ピッカーを開き、名前の変更はツールバーの別ボタンに移すのも検討）
  - 空状態のボタンも「単語を追加」1 つにし、説明文を「単語帳にない単語もここから作れます」に直す
  - `isCreatingWord` と `CustomWordEditorView(mode: .create(addingTo:))` の呼び出しを外す
- `WordPickerView`
  - タイトルを「単語を追加」に。検索欄の文言を「英語か意味で検索（単語帳にない語も追加できます）」などにする
  - 検索語があれば結果の末尾に作成の行を出す（上記 4）。検索語が空のときは、一覧の上に
    「単語帳にない単語は、検索欄に入れると作れます」と 1 行出す
  - 作成の行のロジック（出すか・文言）は View から切り出してテストできるようにする（例: `WordPicker.createAction(query:results:assistAvailable:)`）
- `CustomWordEditorView`
  - 新規作成は `.pick` だけになるので、`.create(addingTo:)` と `targetGroup` まわりの分岐を消す
    （編集 `.edit` は単語詳細から使うので残す）
  - 必要なら `.pick` を `.create(prefill:onPick:)` に改名して意図を分かりやすくする
- `DebugSeed`: `.wordEditor` は「ピッカーから commute を作る」状態で開くように変える（スクリーンショット確認用）

#### 追加（2026-11-03、実機確認で依頼）: AI で調べている間の表示

- エディタを開くと AI チェックが自動で走るようになり、待ち時間が目立つようになった。
  今は「AI チェック」欄に小さな `ProgressView` と文字だけで、処理中だと気づきにくい
- 待ち時間の行を `AssistLoadingView`（`Features/Groups/`）に切り出し、
  - きらめくアイコン（`sparkles` に `symbolEffect(.variableColor)`）と「「○○」を AI で調べています…」
  - その下に、候補が入る場所の骨組み（灰色のバー）をゆっくり明滅させる
  - 「視差効果を減らす」がオンなら動かさない。VoiceOver には 1 つの文として読ませる
- 画面確認用に `DebugSeed` に `word-editor-loading`（エディタを調べている途中の状態で開く）を足す

#### 追加（2026-11-03、実機確認で依頼）: 開いたら検索欄にフォーカス

- 「単語を追加」を開いた直後に検索欄へフォーカスを当て、すぐ入力できるようにする（`DebugSeed` の画面確認時はそちらを優先）

### Phase 2: 管理画面のグループ詳細を 1 つの流れにする（iPhone と同じ機能にそろえる）

2026-11-03 に iPhone の「単語を追加」と突き合わせ、違い ①〜⑥ をすべてこの Phase で埋めることにした
（②・④・⑤・⑥ は Phase 1 のあとに iPhone 側を直したもので、管理画面が追いついていなかった）。

| | iPhone | 管理画面（直す前） |
|---|---|---|
| ① 入口 | 「単語を追加」1 つ | 「単語帳から追加」と「マイ単語を作って追加」の 2 つ。フォームは常に出ている |
| ② 選び方 | 複数にチェック →「追加（N）」でまとめて | 1 語ずつ「追加」 |
| ③ AI の始め方 | 0 件で確定すると自動で走る。結果は同じ画面 | フォームの「AI で調べる」を手で押す |
| ④ 品詞違いの候補 | 1 枚にまとまり、意味ごとにチェック | 別々に並び、手でまとめる |
| ⑤ 同じ綴りのマイ単語 | 置き換える（綴りごとに 1 つ） | いくつでも作れる |
| ⑥ 検索 | 完全一致 → 前方一致 → 部分一致 → 意味 → 例文。上限なし。2 つ目以降の意味も | 前方一致 → 部分一致 → 意味。例文は見ない。50 件まで。グループのマイ単語は出ない |

#### Step 1: 検索をそろえる（⑥）

- `searchWords`（`words/bundled.ts`）の並びを iOS の `WordStore.filter` と同じにする:
  英語の完全一致 → 前方一致 → 部分一致 → 意味（2 つ目以降の意味も）→ 例文（2 つ目以降の意味の例文も）。同じ順位は元の並び
- グループ詳細の検索は同梱語 + マイ単語をひとつの並び（同梱語 → マイ単語の順。iOS の `allWords` と同じ）で順位づけし、件数の上限をなくす
- グループに入っているマイ単語も結果に出し「追加済み」にする

#### Step 2: 1 セクションにまとめ、まとめて追加する（①②）

- 「単語帳から追加」と「マイ単語を作って追加」を **「単語を追加」1 セクション** にする: 検索フォーム → 結果の表（チェックボックス）→
  「選んだ単語を追加」でまとめて入れる（`wordId` を複数送る。`AdminService.addWords` はもともと配列を受ける）
- 検索語が空のときは「単語帳にない単語は、検索欄に入れると AI で調べて追加できます」と出し、作成フォームは出さない
- 検索語があれば、結果の表の下に「「○○」をマイ単語として作る」欄（AI チェック + フォーム）を出す。下書きは検索語から（`draftFromQuery`）
- 入力の誤り・単語帳の語の重複案内で出し直すときは、検索語と下書きを残す
- マイ単語ページ（`/admin/custom-words`）の作成フォームは、グループに入れない単体作成なので残す

#### Step 3: 同じ綴りのマイ単語は 1 つ（⑤）

- `AdminService.upsertCustomWord`: 同じ綴りのマイ単語が無ければ作り、あればいちばん新しく更新したものの内容を置き換える（ID はそのまま）。
  ほかの同じ綴りのマイ単語は、グループでの位置を寄せる先に引き継いでから削除記録を残して消す（iOS の `GroupEditor.upsertCustomWord` と同じ）
- グループ詳細・マイ単語ページの作成はどちらも `upsertCustomWord` を使う。同じ綴りのマイ単語があるときは、作成欄に
  「「○○」はマイ単語にあります。作ると、そのマイ単語の内容を置き換えます」と出す

#### Step 4: AI をそろえる（③④）

- 検索結果が 0 件で AI が使えるときは、作成欄を出すと同時に「AI で調べる」を自動で走らせる（`data-assist-autorun`）
- AI の候補のうち単語帳に無いものは、同じ綴りを 1 枚のカードにまとめ、意味ごとのチェックボックスを付ける（既定はすべてオン）。
  「フォームに入れる」で、チェックした意味をフォームの「意味 1」「意味 2」…に入れる
- 入力どおりの綴りで単語帳に無い語が返れば、そのカードの内容を最初からフォームに入れておく（そのまま「作って追加」を押せば済む）

#### Step 5: テストと確認

- Vitest: 検索の並び・例文・2 つ目以降の意味 / 検索語なしでは作成欄が出ない / まとめて追加 / グループのマイ単語が「追加済み」/
  0 件で AI 有効なら自動実行の属性 / 同じ綴りのマイ単語の置き換えと寄せ
- ローカルでサーバーを起動し、単語帳の語を複数選んで追加 / commute を AI で作る / beautifull で単語帳の語に寄る、を確認

#### Phase 2 の結果（2026-11-03）

- Step 1: `searchWords` を iOS と同じ並び（完全一致 → 前方一致 → 部分一致 → 意味 → 例文。2 つ目以降の意味も）にした。
  グループ詳細の検索は同梱語 + マイ単語をひとつの並びで順位づけし、件数の上限なし。グループに入っているマイ単語も「追加済み」で出す
- Step 2: 「単語を追加」1 セクション。結果の表にチェックボックスを付け、「選んだ単語を追加（N）」でまとめて入れる（1 つも選んでいなければ押せない・送っても 400）。
  検索語が無ければ作成フォームを出さず案内だけ。出し直すときは検索語（hidden の `q`）と下書きを残す
- Step 3: `AdminService.upsertCustomWord` を追加し、グループ詳細・マイ単語ページの作成で使う。同じ綴りのマイ単語があれば作成欄に置き換えの案内
- Step 4: 検索結果が 0 件で AI が使えれば `data-assist-autorun` で開いたらすぐ調べる。単語帳に無い候補は同じ綴りを 1 枚にまとめ、意味ごとのチェック →
  「フォームに入れる」。入力どおりの綴りの候補は最初からフォームに入れる（自分で意味を入れていたら上書きしない）。
  これに伴い、複数の品詞 Phase 4 で付けた「この内容を入れる」「意味として足す」は「フォームに入れる」1 つにした
- Step 5: Vitest 176 件成功・型チェック OK。ローカルでサーバーを起動し Chrome 拡張で確認: commute（0 件 → 自動で調べ、動詞・名詞が 1 枚、
  フォームに意味 1・意味 2 が入り、作ると 1 語）/ もう一度 commute を検索（「追加済み」と置き換えの案内、自動では調べない）/
  home で home・homework にチェック →「選んだ単語を追加（2）」で 2 語入る / beautifull（0 件 → 自動で調べ、単語帳の beautiful を案内）
