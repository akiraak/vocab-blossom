# 単語データ 訳・例文レビュー プラン

作成日: 2026-08-14
親タスク: [単語データの整備](word-data.md)

## 目的・背景

[word-data 仕様](../specs/word-data.md) §5 のとおり、意味・例文・例文訳は LLM 生成のままで
**内容面が未レビュー**。全 2,443 エントリ（A1 1,012 / A2 1,231 / 熟語 200）の
`meaning` / `example` / `exampleJa` の正しさを担保する。

事前の機械チェックで判明した状態（2026-08-14 時点）:

| 項目 | 結果 |
|---|---|
| 例文の語数 | 3〜10 語（平均 5.9）— 仕様の 5〜9 語目安からの逸脱は軽微 |
| exampleJa の句点 | 全件 OK |
| meaning が空 | 0 件 |
| **`meaning` が完全に同一の語** | **79 グループ / 161 語** |
| **例文が完全に同一** | **17 グループ / 36 語** |
| 例文に見出し語が原形で出ない | 353 件（大半は複数形・三単現などの活用形で、英語として自然。要個別判断） |

`meaning` の重複は 4 択クイズで**正解が 2 つある問題**を生む実害があり（例:
excellent / wonderful / fantastic / marvelous がすべて「すばらしい」）、最優先で解消する。

## 対応方針

「人手レビュー」を全 2,443 件について人力で行うのは非現実的なため、
**機械チェック（回帰テスト化）+ LLM による第 2 パスレビュー + 人手スポットチェック** の 3 層で担保する。
生成時とは独立したレビュー観点を与えた別パスで見直すことで、生成時の取りこぼしを拾う。

### Phase 1: 機械チェックをテスト化

`src/data/decks.test.ts` に内容面のガードを追加し、以後の変更でも自動検出できるようにする。

- `meaning` の完全重複禁止（クイズ成立の必須条件）
- `example` の完全重複禁止
- 例文の語数レンジ（4〜12 語）
- 例文が見出し語または**その活用形**を含む（規則変化 + 不規則変化の許容表を用意）
- `meaning` の「／」は 1 個まで（意味は 2 つまで）

### Phase 2: LLM 第 2 パスレビュー（全 2,443 件）

エントリを ~80 件ずつのチャンクに分割し、レビュー用サブエージェントを並列実行する。
各エージェントは**修正提案のみ**を JSON で出力し、適用は本体側でまとめて行う（再現性・差分確認のため）。

レビュー観点:

1. `meaning`: 見出し語の代表的な意味として正しいか / `pos` と一致するか / 初学者向けに簡潔か
2. `example`: 文法・語法が正しい自然な英語か / 見出し語（活用形可）を含むか / A1 文法の短文か /
   その語の意味が伝わる文脈か
3. `exampleJa`: 例文の正確な訳か / 不自然な直訳でないか
4. 文化的・年代的に不適切な内容、初学者に不要な難語が例文に混じっていないか

### Phase 3: 重複解消パス

`meaning` 重複 79 グループ・`example` 重複 17 グループを、グループ単位でまとめて差別化する。
同義語はニュアンスや使い分けを訳に織り込む（例: excellent「優秀な／非常に優れた」/
wonderful「すばらしい／すてきな」）。単なる連番的な言い換えにはしない。

### Phase 4: 適用と検証

- 提案をスクリプトで JSON に適用（ID をキーに `meaning` / `example` / `exampleJa` のみ更新）
- **`id` / `word` / `pos` / `level` は変更しない**（`id` は学習進捗のキーで不変が仕様）
- Phase 1 のテスト + 既存の構造検証テストを全て通す
- 仕様書 §5 のレビュー状況を更新する

## 影響範囲

- `src/data/decks/*.json`（`meaning` / `example` / `exampleJa` のみ）
- `src/data/decks.test.ts`（チェック追加）
- `docs/specs/word-data.md`（レビュー状況の記録）
- MVP 実装側の 4 択誤答肢生成は「同一 meaning を除外」する実装にしておく（データ側と二重の防御）

## テスト方針

- Phase 1 で追加した内容チェックを含む `npm test` を全通過させる
- 適用前後で ID 集合・`word` / `pos` / `level` が完全一致することをスクリプトで検証する
- 修正差分は件数と代表例を残し、人手スポットチェックの入口にする
