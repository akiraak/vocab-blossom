# MVP 実装プラン

作成日: 2026-08-13

## 目的・背景

[app-concept](../specs/app-concept.md) §9 の MVP スコープを実装する。
単語データ（A1/A2 デッキ + 基礎熟語、計 2,443 語）は整備済みなので、その上にアプリ本体
（オンボーディング、学習/復習ループ、庭ビジュアル、単語帳一覧、統計、設定）を構築する。

## 対応方針

### 技術選定（追加依存）

- `dexie` + `dexie-react-hooks`: IndexedDB での進捗保存（コンセプト §7 のとおり）
- `react-router-dom`(HashRouter): 画面遷移。静的ホスティングでも SPA フォールバック設定なしで
  ディープリンクが動くようハッシュルーティングにする（ローカルファースト PWA で URL の見た目は重要でない）
- `fake-indexeddb`(dev): Vitest で Dexie をそのままテストするため

### データモデル（IndexedDB / Dexie）

- `progress` テーブル（wordId が PK）: `stage(1〜5)` / `dueAt`（次回復習日の 0 時、ローカル時刻の ms） /
  `learnedAt` / `updatedAt` / `known`（「もう知ってる」フラグ）
  - **レコードが無い単語 = 種（stage 0、未学習）**とし、種のレコードは作らない
- `answerLog` テーブル: 1 回答 1 行（`wordId` / `answeredAt` / `dateKey(YYYY-MM-DD)` / `correct` /
  `quizType` / `kind(review|new|requeue)` / `stageAfter`）。統計・ストリークはここから導出する
- 設定は `localStorage`（同期読み出しでオンボーディング判定を単純にするため）:
  `level` / `newWordsPerDay`（デフォルト 10） / `reviewLimitPerDay`（デフォルト 60） / `soundEnabled`

### SRS（Leitner）の具体化

コンセプト §3.3 を次のとおり具体化する（日数はステージ**到達時**の次回間隔）:

- stage 1: +1日 / 2: +3日 / 3: +1週間 / 4: +2週間 / 5(開花): +1ヶ月、開花後の維持復習は +3ヶ月
- 復習正解: stage +1（最大 5。5 で正解したら 5 のまま維持間隔）
- 不正解: stage −1（最低 1 = 芽）、翌日再復習にスケジュールし、セッション末尾に再出題（同一カード 2 回まで）。
  再出題での正誤はステージ・スケジュールを変えない（セッション内の確認扱い）
- 新規学習の直後クイズ正解で 0 → 1（芽）。再出題を使い切っても正解できなかった場合も
  芽にして復習ループに乗せる（翌日また出題される方が学習上良いため）
- 「もう知ってる」: stage 4・+2週間 扱い
- 復習上限（60/日）: 期限超過の古い順に上限まで。期限到来数が上限を超えている日は新規語を出さない

### 出題形式（§4 のとおりステージ連動）

- 芽(1〜2): 英→日 4択 / つぼみ(3): 例文穴埋め 4択 / つぼみ(4): 日→英 4択 / 開花・維持(5〜): リスニング 4択
- 新規学習の直後クイズは英→日 4択
- 誤答肢は同レベル・同品詞から 3 語ランダム（不足時は同レベル→全体にフォールバック。意味文字列の重複は除外）
- 穴埋めは例文中の単語を大小文字無視で空欄化。例文に単語が現れない場合（活用形など）は英→日にフォールバック

### セッションフロー（1 本道）

ホームの「今日の学習」→ `復習 → 新規学習（5 語ミニバッチで提示 → 直後クイズ）→ 再出題 → 締め（サマリー）`。
回答ごとに進捗を即保存するので、中断してもやり直し不要（未回答分は期限切れのまま残る）。
ホームのボタンは 1 つに統合し、ラベルとサブテキストで復習◯語・新規◯語を示す（初学者に選択肢を見せない）。

### 画面構成

- `Onboarding`: 初回（設定未保存）のみ。レベル A1/A2 選択 → 保存 → ホーム
- `Home`: 庭（学習済み単語をステージ別の植物 SVG で表示、上限あり）+ ストリーク + 今日の学習ボタン
- `Session`: 上記フロー。回答後は正誤 + 単語カード（意味・例文・音声自動再生）
- `WordList` / `WordDetail`: デッキ別一覧・検索・成長状態 / 意味・例文・音声・次回復習日・回答履歴
- `Stats`: 学習済み語数・開花数・正答率 + 日別回答数（直近 2 週間、CSS バー）
- `Settings`: レベル変更・新規語数/日・音声 ON/OFF・エクスポート/インポート（JSON、置き換え方式）
- 下部タブナビ（ホーム / 単語帳 / 統計 / 設定）。スマホ縦基準、PC は max-width で中央寄せ

### 音声（TTS）

Web Speech API の薄いラッパー（en-US、発話前に cancel、未対応環境では無音）。
提示カード・回答後カードで自動再生、カード上に再生ボタンも置く。

## Phase 分割

- Phase 1: 基盤 — 依存追加、日付/SRS/クイズ生成/セッション構築の純ロジック、Dexie スキーマ、設定ストア、TTS、ルーティング骨格
- Phase 2: オンボーディング + ホーム（庭・ストリーク）
- Phase 3: 学習/復習セッション（提示カード、4 形式クイズ、再出題、締め画面）
- Phase 4: 単語帳一覧・単語詳細
- Phase 5: 統計・設定（エクスポート/インポート）
- Phase 6: 仕上げ — テスト整備、ビルド・PWA・レスポンシブ確認

## 影響範囲

- `src/` 以下の新規追加が中心（`lib/` `pages/` `components/`）。既存の `src/data/` は読み取りのみ
- `App.tsx` / `main.tsx` の書き換え、`package.json` への依存追加
- 単語データ・既存データ検証テストには手を入れない

## テスト方針

- 純ロジック（SRS 遷移・間隔、クイズ生成・誤答肢、セッションキュー構築、ストリーク計算）を Vitest で単体テスト
- エクスポート/インポートは fake-indexeddb でラウンドトリップテスト
- 画面はオンボーディング → ホーム表示のスモークテスト（App.test.tsx を更新）
- 最後に `npm run build` と全テストの通過を確認
