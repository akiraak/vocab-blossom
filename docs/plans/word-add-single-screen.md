# 単語の追加を 1 画面で終わらせる（iOS）

作成日: 2026-11-03

## 目的・背景

- [unified-word-add](unified-word-add.md) の Phase 1 で入口は「単語を追加」1 つになったが、実機で使うと画面遷移が多すぎる
  - 今の流れ: 「単語を追加」（シート）→ 検索 → 「AI で調べて追加する」→ **エディタのシートが重なって開く** → AI の結果を確かめる →
    エディタの「追加」→ ピッカーに戻る → **ピッカーの「完了」** → グループ詳細に戻る
  - 確定ボタンが 2 回（エディタの「追加」とピッカーの「完了」）あり、シートが 2 枚重なる
- 見出しの「N 語を選択中」が、グループに元から入っている語も数えるので「選んでいないのに 1 語選択中」に見える
  （[word-assist-double-select](word-assist-double-select.md) の Step 1 で判明）
- ユーザーが求める流れ:
  1. 追加ボタンを押す
  2. 単語を入れる
  3. 絞り込んで選ぶ。無ければ AI で調べる
  4. 問題なければ「追加」ボタンで追加する

## 対応方針

「単語を追加」の 1 画面の中で、検索・選択・AI の結果の確認・追加まで終わらせる。エディタのシートは重ねない。

### 画面（`WordPickerView` を作り直す）

```
┌ キャンセル     単語を追加     追加(1) ┐   ← 確定はこの「追加」だけ。選んだ数を出し、0 なら押せない
│ 🔍 commute                          │   ← 開いたら検索欄にフォーカス（今と同じ）
├─────────────────────────────────────┤
│ （単語帳の検索結果。タップで ○/● ）   │
│ ● commuter  通勤者                  │
│ ✓ come      来る          追加済み   │   ← グループに入っている語は「追加済み」で灰色、押せない
├─────────────────────────────────────┤
│ ✨ 「commute」を AI で調べる          │   ← 検索語があれば出す（0 件なら中央に大きく）
└─────────────────────────────────────┘

        ↓ AI で調べると、同じ画面の中に結果が出る

├ AI の結果 ──────────────────────────┤
│ ● commute  動詞  新しく作る           │   ← タップで選ぶ（新しく作る語も、単語帳の語と同じ操作）
│   通勤する                           │
│   I commute to work by train.        │
│   [直す]                             │   ← 内容を直したいときだけエディタを開く
│ ○ commute  名詞  新しく作る           │
│   通勤                               │
└─────────────────────────────────────┘
```

- 選択は今と同じく複数選べる。「追加」を押すと、選んだ AI の下書きを自作語として作り、選んだ語を選んだ順にグループの末尾へ足して閉じる
- AI の候補が単語帳の語（打ち間違い・変化形・日本語から）なら、ふつうの単語の行として出し、理由（「綴りの誤りかもしれません」など）を添える
- AI が使えないとき（API キー未設定など）は、AI の行の代わりに「「○○」を自分で作る」を出し、こちらはエディタを開く（今と同じ）
- 外すのはこの画面ではやらない（グループ詳細のスワイプ削除がある）。これで「元から入っている語を数える」問題も無くなる
- 「選んだ語だけ表示」トグルはやめる（選んだ数は「追加」ボタンに出る）

### Step

- Step 1: 画面の状態（検索結果・追加済み・選択・AI の結果）と「追加」で行う処理をロジックに切り出してテストを書く
  - 例: `WordAddSession`（選択の付け外し、追加済みは選べない、AI の下書きの選択、確定で作る自作語とグループに足す ID の並び）
- Step 2: `WordPickerView` を 1 画面の形に作り直す（AI の結果を同じ画面に出す、追加済みの表示、「追加(N)」ボタン）
  - AI で調べている間は `AssistLoadingView` を一覧の中に出す
- Step 3: `CustomWordEditorView` の `.create` を「下書きを直して返す」用途に絞る（「直す」から開き、保存で下書きを差し替える。自作語はまだ作らない）
- Step 4: `DebugSeed` の画面確認用の状態を合わせ、シミュレータ・実機で確認する

### 結果（2026-11-03）

- Step 1〜3 を実装。画面の状態と確定の処理は `Features/Groups/WordAddSession.swift`、テストは `WordAddSessionTests`（9 件）
  - AI の結果のうち、入力どおりの綴りで単語帳に無い最初の 1 つは選んでおく（そのまま「追加」を押せば済む）
  - 単語帳に無い語を入れて検索欄で確定（改行）しても、そのまま AI で調べる
  - あとから別の語で調べ直したときは、遅れて届いた前の結果を捨てる。選んだ下書きは調べ直しても残す
- エディタの新規作成は `.draft(_:posConfirmed:onDone:)`（下書きを返すだけ。自作語は「追加」で作る）にし、エディタ内の AI チェックは外した
- `DebugSeed` に `word-assist-result`（サーバーに聞かずに AI の結果が出た状態）を足した。
  `word-editor-loading` は「単語を追加」の中で調べている状態、`word-editor` は「自分で作る」のエディタを開いた状態
- Swift Testing 181 件成功・SwiftLint 警告 0。シミュレータで AI の結果・調べている途中・追加済み・エディタの表示を確認
- 実機（AI が使える状態）での確認は未実施
